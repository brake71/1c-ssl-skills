# Релизная итерация 5: сигнатура как справка и другая версия

В отдельном `other-version-api-boundary` нельзя отождествлять **описание сигнатуры** 3.1.11 в неисполняемом по смыслу BSL-fence (`Знач Параметр...`) с рекомендацией вызвать её в 3.2.1. Узкий forbidden-паттерн теперь отсекает именно вызываемый `ОбщегоНазначения.СообщитьПользователю(...)`, сохраняя границу версий; парный unit-тест отклоняет runnable вызов без подтверждения. Текст «подтвердить ... 3.2.1 ... нельзя» принимается как явный отказ от переноса, а фраза «можно подтвердить» — нет. Версионных фактов из `bsp321_md/` в поставляемый скил не добавлено.

С прежними правилами полный отдельный 6×3 на распакованном кандидате: `.tmp/release-activation-final-3x.json`, GREEN **6/6 majority, 16/18 individual, gate PASS** (positive activation 3/3, reference 2/2; invalid/unsafe/forbidden 0); RED 3/6 majority. Независимый replay с точным новым scorer: **17/18**, изменился лишь корректный отказ «подтвердить ... нельзя» в версии 3.2.1. Один оставшийся отдельный GREEN отказ — `neutral-platform-exchange-registration` #2, модель не активировала BSP (правильная граница), но придумала **платформенный** `ЗаписатьИзменения` вместо `ЗарегистрироватьИзменения`; не false negative и не исправляется изменением BSP reference. Доступны 24 reference-файла, но в новом независимом корпусе пока охвачены только 2; 6 задач и 3 повтора — малая выборка, не доказывающая общей устойчивости. Прежний guided 27×3 не выдан за тест самостоятельной активации. Исходные JSON не перезаписаны.
