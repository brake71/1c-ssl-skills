# v0.16: источники первой партии activation-сценариев

Внутренний evidence-пилот для авторинга; не часть установленного скила.
Проверка — read-only документация БСП **3.1.11**, затем выгрузка `src/cf`.
Knowledge Vault (`kb/references/bsp-3-1-11-subsystems.md`) подтверждает карту
подсистем, но не используется вместо методных страниц для сигнатур.

|---|---|---|---|

Корпус запрашивает именно ссылку объекта БД и текущего пользователя: он не
проверяет доступ к чужому пользователю в стандартном варианте RLS или объекту
в памяти. У `ПроверитьЧтениеРазрешено` исключение является требуемым эффектом;
сквозной сценарий использует Boolean `ЧтениеРазрешено` для мягкого отказа.

Для сообщения допустимы документированные варианты:

- Поле `"Объект.ДокументОснование"` без ключа данных;
- ключ `Объект` и поле `"ДокументОснование"`;
- поле `"ДокументОснование"` и путь `"Объект"` без ключа.

`Отказ` можно установить явно либо передать пятым аргументом
`СообщитьПользователю`: библиотека установит его в Истина. Одновременные
КлючДанных и ПутьКДанным недопустимы. Required code patterns проверяют
исполняемый пример, а не наличие правильных слов в комментарии.

## Исправление примера хука прав

В `users-access.md` обнаружены три реальных ошибки примера:

1. `ПриЗаполнениеВозможныхПравДляНастройкиПравОбъектов` вместо
   `ПриЗаполненииВозможныхПравДляНастройкиПравОбъектов`;
2. `ВозможныеПрава.Строки.Добавить()` вместо `ВозможныеПрава.Добавить()`;
3. `Право.Описание` вместо документированного `Право.Заголовок`.

Основание: `bsp3111_md/2696_призаполнениивозможныхправдлянастройкиправобъектов.md`
и `src/cf/CommonModules/УправлениеДоступомПереопределяемый/Ext/Module.bsl`.
Дополнительно проверен реальный конструктор таблицы в
`src/cf/InformationRegisters/НастройкиПравОбъектов/Ext/ManagerModule.bsl`,
`ЗаполненныеВозможныеПраваСеанса`: создаётся ТаблицаЗначений с колонками
ВладелецПрав, Имя, Заголовок, Подсказка, НачальноеЗначение и тремя массивами.
Тело хука в поставке пустое — это точка расширения, не прямой прикладной вызов.

Пример исправлен и явно помечен фрагментом внедрения: указан владелец,
инициализированы массивы и названы предварительно настроенные права/типы.
Не добавлять повторно одноимённое право того же владельца. Пример главы 3
показывает заполнение массивов через `.Добавить()` без явной инициализации;
в текущем исходном конструкторе есть типы колонок, но не создание экземпляров
массивов каждой новой строки. В нашем фрагменте эта недоговорённость устранена
явным `Новый Массив` до использования, а не механическим копированием главы.

Регрессия: `tests/test_access_hook_example.py`. Paired controls новых кейсов:
`tests/test_activation_expansion.py`. Совпадение сигнатур и unit-критериев не
является исполнением BSL и не подменяет native behavioral results.
