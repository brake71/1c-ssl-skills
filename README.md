# 1С:БСП Skill

Скил для AI-агента, который помогает применять 1С:БСП 3.1.11 в прикладной
разработке: выбирать реальные общие модули и методы, учитывать контекст
исполнения, отличать стабильный API от служебного и не выдумывать интерфейсы.

## Что входит

Репозиторий поставляет один umbrella-скил `.claude/skills/bsp/`:

- `SKILL.md` — маршрутизация по задачам;
- `references/` — 24 тематических справочника со сценариями, сигнатурами,
  примерами и антипаттернами;
- `scripts/bsp_api.py` — проверка методов и регионов по XML-выгрузке
  конфигурации БСП.

Reference-файлы не являются отдельными скилами. Агент сначала загружает
`bsp/SKILL.md`, затем выбирает один подходящий reference.

## Установка

### Из релиза

Скачайте архив `bsp-skills-vX.Y.zip` на странице
[Releases](https://github.com/brake71/1c-ssl-skills/releases), распакуйте и
скопируйте каталог `bsp` в каталог скилов своего агента.

Для Claude Code:

```bash
unzip bsp-skills-vX.Y.zip -d bsp-skills
cp -r bsp-skills/.claude/skills/bsp .claude/skills/
```

Для OpenCode скопируйте тот же каталог в `~/.config/opencode/skills/` или в
каталог скилов проекта. Другой harness должен уметь читать формат `SKILL.md`.

### Из клона

```bash
git clone --recurse-submodules https://github.com/brake71/1c-ssl-skills.git
cp -r 1c-ssl-skills/.claude/skills/bsp .claude/skills/
```

Submodule `agents-best-practices` используется только для разработки и не
входит в релизный архив BSP-скила.

## Темы

Навигация `bsp/SKILL.md` охватывает:

- базовые утилиты, фоновые и регламентные задания, префиксы и обновление ИБ;
- обмен данными, ЭП/МЧД, классификаторы, контактную информацию, валюты и банки;
- пользователей и доступ, коммуникации, администрирование и мониторинг;
- подключаемые команды, печать, формы, файлы, версии и мультиязычность.

Скил рассчитан именно на БСП 3.1.11. Для другой версии сигнатуры и стабильность
API нужно перепроверять по исходникам соответствующей поставки.

## Проверка API по исходникам

Скрипт принимает обязательный путь к корню выгрузки конфигурации с каталогом
`CommonModules/`:

```bash
python .claude/skills/bsp/scripts/bsp_api.py method СообщитьПользователю --src src/cf
python .claude/skills/bsp/scripts/bsp_api.py module ОбщегоНазначения --src src/cf
python .claude/skills/bsp/scripts/bsp_api.py modules --src src/cf
```

Выгрузка `src/cf/` не распространяется с репозиторием и находится в
`.gitignore`. Без неё reference-файлы остаются пригодны для использования, но
факты нельзя дополнительно подтвердить скриптом.

## Разработка и проверки

Валидатор извлекает API-утверждения из inline-сигнатур вида
`` `Модуль.Метод(...)` `` во всех reference-файлах. Он проверяет обязательный
порог покрытия, существование экспортного метода и заявленный регион. Явные
утверждения «метод не существует» и «не экспортируется» проверяются в обратную
сторону.

Проверка покрытия без исходников БСП выполняется в CI:

```bash
python ci/validate_key_methods.py --coverage-only
```

Полная семантическая проверка выполняется локально с выгрузкой БСП:

```bash
python ci/validate_key_methods.py --src src/cf
python ci/validate_key_methods.py --src src/cf --strict
```

По умолчанию валидатор требует не менее 600 уникальных API-утверждений во всех
не менее чем в 23 из 24 reference-файлов и не менее 95% семантического
покрытия. `fundamentals.md` содержит только концептуальную навигацию, поэтому
не обязан дублировать сигнатуры. Пороги можно
повысить параметрами `--min-claims`, `--min-files` и `--min-coverage`; значения
ниже встроенного минимума валидатор не принимает.

Тесты парсера и валидатора используют синтетические BSL-фикстуры:

```bash
python -m unittest discover -s tests -v
```

GitHub Actions также проверяет компиляцию скриптов, обязательность `--src` для
API-поиска, покрытие references и unit-тесты.
